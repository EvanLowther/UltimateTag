# Ultimate Tag: guide for AI agents

A simple Roblox tag game with a classic studded look. Code lives in files and syncs into Studio with Rojo.


This file is the always-loaded core: what every change needs. The detail is in files read only when they matter (see **Where the rest lives**), so a session starts small. Nothing was dropped when this was split (0.64.0); it was moved.

## Style rules
- **Look:** the test map is studded classic plastic; real maps and the lobby use real materials and lots of non-colliding detail; the UI is the "Street sprint" style built from `client/Menu/Ui.luau` helpers, with **no emoji anywhere** (icons are drawn in code by `client/Icons`). Full rules: `docs/agents/maps.md` and `docs/agents/ui.md`.
- Keep it simple. Prefer one small module per feature over big scripts.

## Conventions
- Every tunable number or name goes in `src/shared/Config.luau`. Never hard-code it in a service.
- A new feature means a new module, required and started from the matching `init.*.luau`.
- Luau, `--!strict` where practical, formatted with StyLua (tabs, 100 columns).

- Cross-cutting rules (details in `docs/agents/modules.md`):
  - Players and bots alike: game code that loops over or looks up contestants uses `shared/Contestant`, never `Players:GetPlayers()` or `.Character` directly.
  - Joints: code that reads or turns a character's joints goes through `client/Joints`, never `IsA("Motor6D")`. Code-built animations go through `client/AnimationBuilder`; joint changes after the animations use `AnimationBuilder.afterAnimation`.
  - Movement: one move at a time (`MoveState.busy`); new moves read `client/MoveState` instead of re-checking; only `client/Crouch` changes HipHeight; only `client/Sprint` sets the field of view.
  - Every tunable is in `Config`; testing tools go in the dev panel; the server owns all game state (see Progression below).

## Finding code (keep sessions small)
- **Code intelligence first.** The real Luau language server, `luau-lsp` (pinned in `rokit.toml`; `tools/lsp/luau-lsp.sh` starts it with the Roblox types and Rojo's sourcemap), gives go to definition, find references, hover types and a file's symbols. Use it instead of reading whole modules; after an edit it reports new type errors in that file.
- Search with `grep -n` and read only the lines you need (offset and limit). The big modules (BotBrain, Config, the menu pages, the victories) run to thousands of lines: never read one whole to change one function.
- **Studio's output**, when the owner has Studio open with "Enable Studio as MCP server" on: the `Roblox_Studio` MCP is allowed read-only tools only (`get_console_output`, `get_studio_state`, `search_game_tree`, `inspect_instance`, `script_read`, `script_search`, `script_grep`). Running code, editing, playtests, input and screenshots are blocked: the owner tests everything themselves. Without it, `~/Library/Logs/Roblox/*Studio*_last.log` has the same errors.

## Checks (run before every commit)
```
tools/check.sh
```
It runs `stylua src`, `selene src`, `lune run tools/check-syntax.luau`, `python3 tools/mapcheck.py` and `rojo build -o build/check.rbxlx` (with `~/.rokit/bin` on the PATH), prints only what failed (the last lines of each failing tool's output) and `checks ok` when everything passed.
**Never build to `UltimateTag.rbxlx`**: the place file holds what only Studio keeps (its settings and anything made there), so rebuilding it from the project would lose that. `build/` is git-ignored. `python3 tools/mapcheck.py` checks the lobby (`src/lobby`) too.

## Workflow
- After each change: keep the docs true where the change touches them (the module's row in `docs/agents/modules.md`, the rules file for maps, UI or sounds, this file for the game flow or a rule), bump `Config.Version`, add a short entry at the top of `CHANGELOG.md` (one to three sentences, see its header), update the README if needed, run `tools/check.sh`, commit, then `git push`.
- Other sessions commit to `main` from this same checkout: `git add` and commit explicit paths only, never `git add -A` or `git commit -a`.
- Commit message format: `area: what changed` (for example `map: add obstacle course`).
- No co-author, AI attribution or session lines in commit messages (no `Co-Authored-By`), and nothing in the repo names the AI tools used to build it.
- GitHub: https://github.com/EvanLowther/UltimateTag (private). The `.rbxlx` file is built by Rojo and git ignores it.


## Features
## Features
**Game flow (0.26.0).** `Config.Game.Mode = "Elimination"`: players wait in the lobby; with `MinPlayers` (Studio: `StudioMinPlayers`) a `LobbyCountdown` starts, then a game. Each round MapService picks a map for the number of players still in, everyone is placed on its spawn points, the game mode makes as many Its as the round's elimination target (`shared/RoundPlan`, at most `MaxRounds` 5 rounds), everyone is frozen for `IntroTime` (5 s, the Its too; the role banner shows 3 s of it), then the round timer runs (`RoundTimes`: 2:00 with 7+ players left, 1:30 with fewer). The round ends the moment the target are out (falls on the Rooftop District, the Metro's train, AFK, leavers) and a new It is picked if none is left; at the timer the Its still It are eliminated (up to the target). The lobby countdown starts at `LobbyCountdown` 20 s, each join adds `JoinExtend` 10 up to `CountdownCap` 40, a lobby of `BigLobby` 10 is cut to `BigLobbyCut` 15. Tags freeze nobody. When it ends the mode decides who is eliminated: they stay visible, frozen and flashing for `EliminatedTime` (the ELIMINATED moment), then their body is parked (anchored, invisible, no collision, under the lobby: `Config.Game.ParkOffset`) and they are camera only, spectating (Q/E or the on-screen prev/next buttons to switch; controls off). Falling out and joining late park the same way. Rounds continue on new maps until one player is left: they win (+1 Win). When the game ends everyone is respawned in the lobby at once (spectating stops), and the win screen plays for `VictoryTime` (client/WinScreen). While a game is on, swings and tags from and on anyone not still in it are ignored. Anyone can swing (left click, a swipe): It's swing tags a Runner in reach while a round is Playing (a player's screen picks who: within `Config.Tag.PlayerRange`, or `AimRange` near the aim ring; a bot's within `Range`); any other swing (a Runner's, It with no Runner in reach, or in the lobby) shoves the nearest player in reach. Every hit knocks the player back (`Config.Knockback`): harder the faster the swinger was moving at them, harder again if they're in the air. Test with 2+ players in Studio (Test > Clients and Servers > Local Server), or alone: with `Config.Bots.Enabled` one player starts the countdown and bots fill the game up to `Config.Bots.FillTo` (`server/Bots`, `server/BotBrain`; a game with bots pays 10% less per bot).
- Game modes live in `src/server/Modes/`. Each has `Name`, `setup(players, target) -> status text`, `finish(players, quota) -> eliminated` and The first is **Hot Potato** (`Modes/HotPotato.luau`): as many players start as It as the round's target, tagging passes It, whoever is It when time runs out is eliminated (the ones who held it longest first if the target is partly met). To add a mode, add a module with that shape and point `GameLoop`'s `mode` at it.
- `Config.Game.Mode = "Sandbox"`: the old free-play test mode on TestGround (one It, nothing ends) for movement testing. The dev panel switches modes while the server runs (`GameLoop.setMode`).

## Progression and rewards
Coins and XP come from playing (games, rounds survived, tags, wins, minutes played, and moves during rounds: `Config.Progression`). Levels pay coins, a free crate every 5 levels and exclusive cosmetics at set levels. Cosmetics (trails, tag effects, titles, victories; `shared/Catalog`) come from the daily shop (changes at 00:00 UTC; never Iridescent), the Mystery crate (bought in the Shop, opened in Rewards; odds shown, duplicates possible), levels, the login streak and achievements. Rarity sets the look: Common one color, Rare two colors or a simple pattern, Epic a gradient, Legendary a gradient plus effects, Iridescent shifting holo colors plus something special (afterimages, Shatter, a framed title with its serial number, a holo statue), with a server-wide shout-out when one is unboxed. Victories are Epic and up. Exclusive (green) items are only earned. Daily and weekly quests, achievements and the 7-day streak track themselves and are claimed by hand. Everything is saved in one profile per player (server/PlayerData). Test with the dev panel's **Progress** tab: give coins/XP/crates, unlock everything, finish quests, and move the calendar forward a day or week. Saving needs API access in Studio (Game Settings > Security); without it everything works for the session.

Rules of thumb:
- Anything a player earns goes through `Progression.record` (events) or `Progression.grant` (reward bundles), never by editing coins directly, so popups, quests and achievements all see it.
- Testing tools go in the dev panel: a new server command is a handler in `server/DevCommands.luau` (it already checks access), a new tunable is a line in `Config.DevPanel.Tunables`.
- Server owns all game state. Clients read attributes and ask the server through RemoteEvents in `shared/Remotes.luau` (add new names to its list).
